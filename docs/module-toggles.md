# 模块启停

配置入口：模组列表 → Avaritia: Integration → 配置。选择模块后点击启用/禁用，再点击保存；取消或 Esc 丢弃未保存的草稿。重新读取会丢弃草稿并重新读取磁盘配置。

配置存于游戏目录下 `config/avaritia/integration/load_rules.json`，每条现有规则可增加布尔字段 `enabled`，省略时视为启用。例如：

```json
{
  "avaritia_integration_create": {
    "enabled": false,
    "dependencies": [{"modid": "create", "minVersion": "", "maxVersion": ""}]
  }
}
```

启用表示允许加载，仍须满足上游依赖及版本规则。Mekanism Generators 联动依赖 Mekanism 联动；IFEU 联动依赖 Industrial Foregoing 联动，关闭所需模块时相应扩展也会跳过。已有配置缺少某条模块规则时仍保留原先的“缺少规则”行为，需要管理员补齐规则。

列表分别显示本次启动状态和下次启动意图；修改后先显示“未保存”，保存后显示“待重启”。代码注册、Mixin 行为和内嵌数据包共用本次启动决定，保存或重读配置不会在运行中撤销已注册内容。必须完全退出并重启游戏或专服才能切换。加载器仍会发现模块 JAR，界面中的禁用控制的是联动内容和行为，不会物理卸载 JAR 或 Mixin。

配置只作用于本地安装。多人服务器需由管理员维护服务端规则，并使客户端内容配置一致。禁用含有方块或物品的模块会移除对应注册项，已有世界中的这些内容可能丢失；应先备份世界。重新启用恢复注册项，并不承诺恢复禁用期间丢失的世界内容。

保存只修改发生变化的 `enabled` 字段，保留其它依赖及未知 JSON 字段（格式及注释不保留；JSON 本身不支持注释）。保存前比对读取时的完整文件；检测到外部改动时拒绝覆盖，保留界面草稿并要求重新读取。格式损坏或 `enabled` 非布尔值时禁止保存并显示读取失败。

持久化顺序：持有兄弟 `.lock` 文件锁 → 检测并清理遗留 `.tmp`，记录警告 → 写入同目录 `.tmp` → 完整写入及文件 fsync → 再次比对原文 → 原子替换 → 父目录 fsync。不支持原子替换时保存失败，不降级为非原子写入。替换后父目录同步失败报告“已保存但持久性警告”；替换后重读失败也报告已保存的警告，避免误报为完全未写入。

文件锁用于协调本功能的写入者；外部编辑器若不使用此锁，最后一次比对与原子替换之间仍存在很短的竞争窗口。配置保存期间应避免其它程序同时写入。孤儿临时文件从不覆盖正式配置；恢复保留最后一次已提交的正式文件。
